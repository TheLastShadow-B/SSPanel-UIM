# 节点回国 TCP 状态

节点列表按 CT（电信）、CM（移动）、CU（联通）的顺序显示当前状态色，详情页也使用相同简称。点击节点名称或三网状态进入详情，查看最近约 24 小时的 96 格历史条（每格 15 分钟，包含当前未结束时段），展开运营商查看各目标最新结果。

## 部署

动态目标功能需要同时更新面板和 XrayR，并运行最新迁移。迁移保留已有目标的 ID、运营商和地址；旧版 XrayR v1.0.6 最多接受 9 个目标，超过后不会上报。

1. 更新面板代码，在面板目录运行 `php xcat Migration latest`；发布仓库里的 `public/theme/cafe/app.css` 构建产物。
2. 编译并部署同次修改后的 XrayR，重启一次。后续检测配置更新不需要重启。
3. 打开后台 **节点 → 回国检测**，点击「新建测试目标」，选择 CT / CM / CU 并填写名称、IP、端口。目标按需创建，不再预留固定数量；点击已有目标可修改或删除。目标使用公网 IPv4 和开放的 TCP 端口，建议选取多个地区、自有或允许探测的稳定端点。运营商归属需要管理员确认，系统不会根据名称猜测归属。
4. 在同一页面开启相应节点的检测，设置黄色延迟阈值（默认 250 ms）。
5. 保持现有 `php xcat Cron` 五分钟任务，用于清理超过 7 天的检测记录。

XrayR 复用已有 SSPanel `APIHost`、`APIKey`、`NodeID`，面板复用 `/mod_mu` 的 `NodeToken` 鉴权、IP 检查和已有访问限速；不增加凭证。必须使用 HTTPS 面板 API。老 XrayR 不会上报，面板显示灰色；新版 XrayR 连接没有检测接口的老面板时，404 被视为未启用，不影响代理服务。

XrayR 使用系统 TCP socket，每轮向每个目标建立 3 次连接，每次最长 3 秒，同一目标间隔 200 ms，最多并发 6 个目标。成功后立即关闭，不发送应用层数据。按节点编号错开 1–10 秒启动；最多 24 个目标时每 60 秒一轮，更多目标按每批 6 个、每批预留 10 秒及 API 预留时间自动延长周期（向上取整至整分钟）。例如 25–60 个目标每 120 秒一轮。检测任务不重叠，始终最多 6 个工作线程。检测任务随控制器关闭而取消，不重建代理入站。

检测使用 `ControllerConfig.SendIP` 作为源地址（空值、`0.0.0.0`、`::` 使用系统默认 IPv4 出口），不经过 Xray 的路由/代理规则。因此结果代表节点主机对应源地址的直接网络连通性，而非用户代理请求经过复杂分流后的完整业务链路。首版不支持 IPv6 目标或 IPv6-only SendIP。

## 状态规则

- 绿色：本轮全部目标的 3 次连接都成功，每个目标成功样本的中位耗时均不超过阈值；连续两轮确认。
- 黄色：有目标连接失败，或任一目标的中位耗时超过阈值，但至少一次连接成功；连续两轮确认。
- 红色：所有目标全部连接失败，连续三轮确认。
- 灰色：未配置/未启用、首次检测尚未确认、配置修改后等待新数据、超过 3 个检测周期未收到新数据。

状态确认期间沿用上次已确认状态；恢复绿色也需要连续两轮。漏过一个检测周期或配置版本变化会重置连续轮次。TCP 连接拒绝算连接失败，但保留 `refused` 原因，不能据此认定整个运营商网络不可达。本地源地址绑定或文件描述符资源失败会丢弃整轮，不误记为线路中断。

历史格保留区间内最严重的已确认状态：红 > 黄 > 绿。没有已确认异常且有效数据覆盖不足 80%，或包含未确认的灰色结果时，格子显示灰色。点击/聚焦色块显示时间、连接成功率和数据覆盖率。历史保留当时的配置和判定，不因修改阈值重算。

右上角可用率 = 至少一次目标连接成功的轮数 / 有效检测轮数；缺失数据不纳入分母，旁边另显示覆盖率。黄色的高延迟轮次仍算可用。TCP 建连耗时包含往返路径与协议栈处理，不是单向时延、下载带宽或真实数据包丢包率。

## 接口契约

检测周期由 `interval_seconds` 返回，历史覆盖率按每轮记录的周期计算。

`GET /mod_mu/nodes/{id}/tcp-probe?key=...` 返回 `{ret: 1, data: {enabled, threshold_ms, interval_seconds: 60, timeout_ms: 3000, attempts: 3, config_hash, targets: [{id, carrier, label, ip, port}]}}`。目标列表独立于节点配置接口，改变目标不会导致 XrayR 重建入站。

`POST` 同一路径，JSON 正文：

```json
{
  "config_hash": "GET 返回的版本哈希",
  "measured_at": 1800000000,
  "results": [
    {
      "target_id": 1,
      "samples": [
        {"latency_ms": 123.45, "error": null},
        {"latency_ms": null, "error": "timeout"},
        {"latency_ms": 124.1, "error": null}
      ]
    }
  ]
}
```

必须完整上报配置中的全部目标，每个目标恰好三次。错误枚举：`timeout / refused / unreachable / other`。时间允许落后面板 120 秒、超前 30 秒，节点需同步系统时钟。服务器重新计算耗时和状态，不信任客户端提交颜色；拒绝过期配置和不完整报告。按节点和采样分钟去重，延迟/重复上报不覆盖新状态。历史数据不向普通用户暴露目标 IP 或任何 API 凭证。
